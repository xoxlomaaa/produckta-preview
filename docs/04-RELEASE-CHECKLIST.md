# Техническая приемка сайта

Версия 1.3. Использовать вместе с заполненным профилем проекта. Этот список проверяет программную реализацию; параметры дизайна и конкретная схема адаптации задаются заданием сайта.

Пустой checkbox означает «не подтверждено». Для нового релиза проверить все применимые пункты; для локальной правки — затронутый сценарий и вероятные регрессии. Неприменимые пункты пометить с причиной.

## 1. Структура и сборка

- [ ] Границы templates/data/styles/behavior/backend понятны и соответствуют профилю проекта.
- [ ] У модулей и компонентов определены владельцы, входные данные и зависимости.
- [ ] Исходники отделены от build output и публичной области.
- [ ] Runtime/зависимости зафиксированы; чистая установка и production build воспроизводятся по README.
- [ ] Статические проверки выполнены, замечания разобраны по смыслу.
- [ ] Нет ручных изменений minified output, потерянных исходников и цепочек файлов исправлений.
- [ ] В публичном артефакте нет секретов, рабочих архивов, отчетов и ненужных инструментов.

## 2. HTML, данные, маршруты

- [ ] Основной контент приходит из определенного источника и не расходится между слоями.
- [ ] Семантика HTML, labels, заголовки, landmarks, уникальность IDs и ARIA-связи корректны.
- [ ] Данные экранируются по контексту; закрытая config не попадает в браузер.
- [ ] Индексируемый контент доступен согласно модели рендеринга проекта.
- [ ] HTTP statuses, переходы, прямые ссылки, метаданные и canonical соответствуют маршрутам.
- [ ] Canonical, внутренние ссылки, редиректы и sitemap согласованы. Контрольные URL имеют ожидаемый статус, включая 404 и перенесённые страницы.
- [ ] Robots, noindex и правила доступа проверены отдельно на production и предпросмотре. Структурированные данные валидированы, если используются.
- [ ] Мобильная версия сохраняет основной контент и ссылки. Опубликованные URL проверены в кабинетах целевых поисковиков при наличии доступа.
- [ ] Внутренние ссылки и локальные assets не имеют неожиданных ошибок.

## 3. SCSS/CSS и адаптивная логика

- [ ] Entry points и порядок каскада явные, общие зависимости не дублируются без причины.
- [ ] При mobile-first проверены базовые правила на узком экране и расширения на широком. Порядок CSS-слоёв и внешних стилей проверен в собранном CSS, если они используются.
- [ ] Изменения находятся в модуле-владельце; соседние компоненты не меняются побочными селекторами.
- [ ] Условия адаптации принадлежат проекту/компонентам и соответствуют профилю.
- [ ] Используемые совместно условия CSS и JS согласованы.
- [ ] Проверены границы и переходы выбранных в проекте режимов, а не только начальная загрузка.
- [ ] Смена режима сохраняет нужные данные, активное состояние и управляемый фокус.
- [ ] Нет дублирующихся IDs, listeners, observers, запросов или независимых состояний одной формы.
- [ ] Неактивный вариант не остается неожиданно фокусируемым или работающим в фоне.
- [ ] Проверены целевые браузеры, способы ввода, ориентация, масштабирование и клавиатура согласно профилю.
- [ ] Неожиданное переполнение, обрезание или потеря функции устранены; предусмотренная проектом прокрутка не считается ошибкой сама по себе.

## 4. JS, состояния, доступность

- [ ] Повторные init/update/destroy безопасны, экземпляры имеют одного владельца.
- [ ] Listeners, observers, timers, rAF, animations и requests освобождаются.
- [ ] Поздний async-ответ не меняет уничтоженный/переоткрытый компонент.
- [ ] Ошибка независимого модуля не останавливает остальные; fallback соответствует сценарию.
- [ ] Menu/tabs/select/dialog проверены клавиатурой; DOM/ARIA отражают реальное состояние.
- [ ] Для modal проверены initial focus, фон, Tab/Escape, вложенность и возврат фокуса.
- [ ] URL, прямые ссылки, Назад/Вперед и bfcache работают без случайной повторной инициализации.
- [ ] Пользовательские настройки и требования доступности проверены в пределах профиля проекта.
- [ ] Отказ загрузки JS и внешнего сервиса приводит к определенному состоянию, а не ложному успеху.

## 5. Формы и backend

- [ ] Endpoint, поля, серверная валидация и схема ответа соответствуют контракту.
- [ ] Проверены empty/invalid/submitting/success/error/timeout/cancel/retry и close/reopen.
- [ ] Повторное действие не создает неконтролируемые дубли; ввод сохраняется при неуспехе.
- [ ] Ошибки связаны с полями и доступны предусмотренным способом.
- [ ] CSRF/origin/auth/anti-abuse проверены в разрешенной среде согласно модели backend.
- [ ] Нет секретов в коде/публичной config и чувствительных данных в диагностике.
- [ ] Сообщение успеха соответствует реальному подтверждению доставки/очереди/операции.
- [ ] Прокси, сессии, rate limiting и число инстансов учтены конфигурацией.

## 6. Загрузка и производительность

- [ ] Маршрут получает нужные CSS/JS entries, тяжелые дополнительные зависимости имеют условие загрузки.
- [ ] Проверено, какие файлы действительно запрашиваются в каждом целевом режиме.
- [ ] Picture/srcset/sizes и font-face соответствуют ресурсам и проектной адаптации. Форматы изображений сверены по весу и визуальному качеству.
- [ ] LCP/lazy/preload/priority согласованы; нет лишних повторных загрузок и непреднамеренных сдвигов.
- [ ] CSS-скрытие не используется как доказательство отсутствия загрузки/исполнения.
- [ ] Asset manifest, хеши и cache policy согласованы с публикацией HTML.
- [ ] На реальном сервере проверены HTTPS, смешанный контент, сжатие, MIME, кеширование и правила доступа.
- [ ] Замеры сделаны на production build по профилям и сценариям этого проекта.
- [ ] Бюджеты и метрики сравниваются с профилем проекта, а не с размерами предыдущего сайта.
- [ ] Оболочка и сценарий после подключения внешних сервисов проверены отдельно.
- [ ] Сохранены условия серии Lighthouse-прогонов, медианы, разброс и значения метрик по маршрутам.
- [ ] Анимация проверена с прокруткой и на слабом мобильном профиле. Статичный кадр в reduced motion передаёт тот же смысл.
- [ ] Лабораторные результаты и полевые данные зафиксированы отдельно. Если полевых данных пока нет, это отмечено.

Методика и стартовые бюджеты приведены в [руководстве по производительности](05-PERFORMANCE-PLAYBOOK.md).

## 7. Передача результата

- [ ] Документация описывает фактические команды и структуру.
- [ ] Есть процедура публикации, проверки контрольных URL и восстановления предыдущей версии.
- [ ] Назначен владелец послерелизной проверки формы, ошибок и индексации. См. [порядок выпуска](06-SEO-AND-RELEASE.md).
- [ ] Указаны выполненные проверки, среда, версия кода и непроверенные условия.
- [ ] Сохранены необходимые доказательства, относящиеся к изменению.
- [ ] Архитектурные исключения имеют причину и владельца.
