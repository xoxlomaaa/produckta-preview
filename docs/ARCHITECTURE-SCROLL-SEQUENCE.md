# Архитектоника: последовательность прокрутки без фокуса

12.11.2026. Реализовано по запросу пользователя. Скиллы diagnosing-bugs и adapt. Это проверка узла прокрутки, не общий Lighthouse/приёмка всего сайта.

## Что было сломано

1. Превью получало колесо только через обработчик внутри iframe. При неподвижном курсоре в боковом поле основная страница проходила дальше, внутри оставался первый экран. Воспроизведение на 2560×1440 в обе стороны: input 600px целиком двигал родителя, child оставался 0 / 8294. Команда check-architecture-stationary-repro.cjs before; исходный red-отчёт — output/qa/architecture-stationary-scroll/before.json.
2. До загрузки embed.js пустой iframe не имел wheel-моста. Даже курсор по центру мог позволить браузеру нативно проскочить центр до готовности JS. Это воспроизвёл непрерывный прогон 390px без ожидания ready.
3. Во время смены документа scrollingElement кратковременно равен null. Прежнее вычисление scrollHeight выбрасывало исключение, первое колесо оставалось без preventDefault и также пропускало центр. Воспроизведено на 320px, исправлено безопасным измерением границ во время загрузки.
4. В низких окнах нужно было уместить рамку, сохранив внутренние 650px для горизонтальной сцены. После масштабирования браузер мог округлять эту высоту до 649px и включать вертикальный fallback. Добавлен запас 652px; фактический innerHeight после подгонки 651–652px. Горизонтальная сцена донорского сайта не переписана.

## Текущий механизм

- Превью регистрируется один раз в общем контроллере через registerPreview(read, ownerSignal). Маршрутизация вертикального колеса/трекпада определяется последовательностью страницы и направлением, независимо от положения курсора и кликов. Из iframe события попадают в ту же очередь, а не во вторую анимацию.
- Сначала движется основная страница до центра всей .cap-site-shell (вместе с верхней браузерной панелью). Затем прокручивается дочерний документ. На границе ребёнка остаток ввода продолжает основную страницу; обратный ход симметричен. После выхода нет повторного захвата при движении от секции.
- Частоты пружины, ограничение очереди и темп чемодана сохранены. queuedDistance, фактический route и positionAt используют общий маршрут. Допуск 1px оставлен для округления координат браузером.
- Lazy-load начинается за 1000px до области. Пока iframe пустой/не готов, aria-busy=true отключает попадание указателя именно в iframe; колесо получает родительский контроллер. При достижении центра остаток ввода хранится без холостого RAF-цикла.
- embed.js сообщает produckta:preview-ready после window.load, document.fonts.ready и двух RAF. Владелец включает указатель и через refreshPreviews продолжает сохранённое движение. Дополнительный клик/новое колесо для старта не нужны.
- При ожидании можно уйти назад. Ошибка документа без embed или error освобождает очередь; 12-секундный предохранитель исключает бесконечное ожидание. Поздняя готовность не возвращает пользователя назад. 503 и зависшая загрузка с поздним успехом проверены.
- В низком окне .cap-site-shell пропорционально подгоняется CSS zoom до innerHeight−32px, не расширяя физическую ширину контейнера. Внутренний viewport desktop сохраняет минимум 650px и горизонтальный GSAP-механизм. На больших окнах scale=1 и прежняя геометрия сохранена. При resize в активном центре рамка остаётся по центру, дочерняя позиция не сбрасывается.

Состояния/таймер принадлежат src/showcase/architecture-preview.js; общая очередь — src/js/smooth-scroll.js; подтверждение готовности и пропуск настоящих вложенных скроллеров — src/showcase/architecture/embed.js; fit/input CSS — src/showcase/showcase.css. Все listeners/таймеры/регистрации снимаются при destroy. Новых библиотек, правок minified donor CSS/JS или дополнительного scroll-spacer нет.

## Что проверено

17 полных сценариев, 15 размеров: 320×740, 375×812, 430×932, 844×390, 390×844, 768×1024, 1024×768, 1280×720, 1366×600, 1440×900, 1920×1080, 2560×1440, 2048×1152, 3440×1440, 3840×2160.

На Quad HD три фиксированных положения курсора: боковое поле, центр, верх окна. Отдельный проход начат с Hero, без программного переноса к превью. Полные сценарии идут до конца внутреннего документа, затем выходят на основную страницу и проходят назад; кликов нет. Проверены отсутствие пропуска незавершённого превью, центрирование при движении внутри, полнота рамки, физическая ширина, отсутствие горизонтального переполнения и выполнение горизонтальной сцены на desktop. DPR 1.25 проверен отдельно как браузерная эмуляция масштаба, не как физический монитор.

- check-architecture-stationary-repro.cjs: минимальный red/green для курсора в поле QHD.
- check-architecture-stationary-matrix.cjs: matrix.json, снимки preview-*.png; все 17 сценариев пройдены, ошибок JS нет. Проверка конечной позиции не заменяет видимость: RAF-трассы дополнительно проверены check-architecture-centre-invariant.cjs (допускается один совместный шаг на границе child+parent).
- check-architecture-readiness.cjs: задержанный документ, сохранение 480px ввода, разворот во время загрузки, precision/reduced motion, 503. Без дополнительных действий после готовности очередь продолжилась.
- check-architecture-timeout.cjs: отсутствие готовности более 12s освобождает очередь; поздний success не меняет позицию родителя назад.
- check-architecture-resize-touch.cjs: активный центр QHD → FHD → 1366×600 → телефон → QHD, внутренняя позиция около 2000px сохраняется. Нативный свайп в готовом мобильном iframe прокрутил его на 411px без сдвига родителя.
- Старые проверки частичного входа, обоих handoff и горизонтальной сцены прошли. Прокат/строительный viewer/чемодан проверены функционально отдельным check-locker-roof-compatibility.cjs на 390/1024/1920.

Все новые отчёты — output/qa/architecture-stationary-scroll/. Синтаксис изменённых модулей, сборка, палитра, статические ссылки/бюджеты пройдены. Визуально просмотрены QHD и низкое окно с целой рамкой.

## Границы

Автоматическая последовательность относится к колесу и вертикальному вводу трекпада. Для touch сохранено нативное поведение: свайп над iframe листает его, вне iframe — основную страницу; перехват всей пальцевой прокрутки не добавлялся. Внутренние поля/настоящие вложенные скроллеры и открытые модальные окна не перехватываются. Клавиатура, якорные переходы и ручное перемещение основного scrollbar не принуждаются к просмотру превью. Reduced motion не добавляет пружинную анимацию.

Проверки выполнены в Chrome через Playwright; физический Quad HD-монитор, физические телефоны, Safari и Firefox не проверялись. «Все разрешения» не означает проверку бесконечного набора размеров; выше перечислены фактические точки и переходы. Локальный сервер выдаёт Cache-Control:no-store, после обновления JS нужна перезагрузка открытой вкладки.
