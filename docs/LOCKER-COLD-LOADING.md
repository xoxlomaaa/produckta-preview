# Холодная загрузка чемодана · 12.11.2026

Сохранены все 265 позиций таймлайна, камеры, anchors, wheelPace=1.15 и общая прокрутка.

`tools/prepare-locker-frames.mjs` готовит WebP quality 74 / alpha 100 из оригиналов render-v1. Desktop сохраняет 1152/1440px; mobile имеет 75% прежней ширины. Исходные габариты в manifest сохраняют прежние координаты и масштаб мобильного выреза. 16 hash-пакетов для всех камер находятся в `assets/showcase/locker/assets/render-v3/`; посетителю нужны обычно 7. Внутри до 48 кадров; `config/frame-packs.mjs` хранит URL, размеры/смещения и исходные габариты. Чтение через Blob.slice, backend не нужен.

`frame-source.js` скачивает сжатые пакеты двумя запросами параллельно, по первому нужному кадру. В фоне используется low, при подходе к сцене новые запросы получают auto: сохранение low у видимого контента приводило к большой задержке в публичном мобильном прогоне. Обратный ход не скачивает пакеты заново. При отказе доступны исходные WebP. `showcase.js` запускает подготовку через секунду после window.load; Save-Data отключает раннюю загрузку. Облака запускаются по прежней близости к сцене.

До готовности сжатой последовательности и первого окна bitmap показывается настоящий постер; прокрутка свободная. Окно распакованных кадров ограничено: 24 mobile / 40 desktop, декодирование 4/8. Исправлен буфер при обратном ходе к кадру 1; смена камеры/границы 540px пересоздаёт источник. Pagehide освобождает ресурсы, reduced motion не загружает пакеты.

`roof.js`: автокомпиляция Three.js/шейдеров ждёт ухода предыдущей сцены с экрана. Пересечение нагрузок подтверждено CPU-профилем. Ручная загрузка остаётся немедленной; сама модель и управление не менялись.

## Проверка

Chrome headless / Windows, отдельные холодные контексты, cache disabled. Основной профиль: 4 MiB/s / latency 40ms / CPU ×4. Сценарий: быстрый переход к сцене, отдельно замеренное ожидание первого кадра, 34 импульса колеса по 120px каждые 90ms, 600ms покоя, такой же обратный ход.

- До: вперёд кадр 178 при цели 265, назад 151 при цели 1; максимум 729,9ms, 8 пауз >100ms. `output/qa/locker-loading/before-1920.json`.
- После: контрольные проходы 390/1024/1920/2560 достигают 265/1, без пауз >100ms и скачков >3 кадров. Последняя защита полного буфера отдельно проверена на mobile и desktop. Отчёты `after-cold-*`, `after-lead-*`.
- Более медленный профиль 1 MiB/s / 100ms / CPU ×4: 13,8ms между сменами кадров в движении, обе цели достигнуты. При мгновенном прыжке из начала страницы постер ожидал 7,7s: данные ещё нужно получить. При 5s чтения верхней части на основном профиле ожидание около 67ms.
- Финальный mobile: постер 1,16s при мгновенном переходе, без отставания/пауз >100ms. Нативный touch, переключения 390/600/1024/1920, отсутствие переполнения и reduced motion без пакетов — `compatibility.json`.
- Просмотрены сравнение качества desktop и кадр мобильного нативного прохода. Prefixed production-сборка: iframe, крыша auto-ready, админка, меню и политика работают; нет JS-ошибок/404/запросов мимо prefix. `output/publish/subpath-check.json`.
- Unit проверяет байты/границы 16 пакетов, исходные размеры, один запрос на пакет, fallback, отмену и освобождение позднего bitmap. Включён в Actions.

Финальный публичный mobile на основном замедленном профиле: постер 1654ms, нет пауз >100ms/отставания, 9 запросов, нет JS/HTTP-ошибок.
