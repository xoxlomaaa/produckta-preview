# Входная анимация главной

12.11.2026. Этот документ описывает согласованный вход Hero и образец «Идеи — в дело». Общая анимация остальных контентных разделов теперь описана в [CONTENT-MOTION.md](CONTENT-MOTION.md). Контроллер прокрутки и интерактивная витрина не изменялись.

После общего входа добавлено короткое покачивание утки раз в пять секунд. Контракт и актуальная проверка этого дополнения — [HERO-DUCK-IDLE.md](HERO-DUCK-IDLE.md).

## Разбор и решение

| Before | After | Why |
|---|---|---|
| Статичный трамплин, отдельная траектория утки | Движение всей `.hero-art`, исходный цельный SVG | Персонаж, скейт, точка и трамплин всегда сохраняют взаимное положение |
| Заголовок двигался по строкам, описание и CTA оставались статичны | Один заголовок и согласованные входы описания, CTA, опыта, шапки и фона | Первый экран воспринимается общей сценой |
| Независимые старты | Единая `document.timeline.currentTime` и короткие интервалы между группами | Исключены случайные рассогласования |

## Владельцы и границы

- `src/js/page-motion.js` — Web Animations API, общий lifecycle и ограниченный набор целей. Новых библиотек или обработчиков wheel нет.
- `src/styles/page-motion.css` — адаптивные параметры и строки заголовка. Порог 48rem принадлежит CSS; JS читает custom properties.
- `assets/illustrations/duck-ramp.svg` — неизменённый оригинал. Для покачивания возвращены его точные производные `hero-ramp-layer.svg` и `hero-duck-layer.svg`; общий вход по-прежнему двигает их вместе через родителя. Совмещение пиксельно совпадает с оригиналом.
- Область анимации: Hero, его шапка и фоновый элемент, `#scenes`, `#process`. Родители интерактивной витрины не трансформируются.

## Hero: единый вход

Перед началом JS готовит семь групп. Старт после готовности шрифта и SVG, с ограничением ожидания 350ms. Загрузочного экрана нет. Без JS, нужных API или при reduced motion подготовительное скрытие не применяется.

Все участники на экране получают один `startTime`. Easing `cubic-bezier(.25,.46,.3,1)`. На телефоне времена умножены на 1200/1450; CSS задаёт меньшие дистанции. После завершения эффекты не удерживают transform/opacity.

| Группа | Начало / длительность на desktop | Движение |
|---|---|---|
| Фоновая петля | 0 / 1600ms | Только прозрачность |
| Шапка: логотип, навигация, CTA либо мобильное меню | 0 / 750ms | −12px по вертикали → 0, прозрачность |
| Сцена `.hero-art` целиком | 80 / 1450ms | Подъём с 72px (телефон 42px), масштаб .98 → 1, прозрачность |
| Заголовок целиком | 160 / 1100ms | Подъём с 40px (телефон 28px), прозрачность |
| Описание | 280 / 1050ms | Подъём с 24px (телефон 16.8px), прозрачность |
| Кнопка обсуждения | 380 / 950ms | Тот же короткий подъём, прозрачность |
| Опыт основателей | 440 / 1000ms | Только прозрачность; движется вместе с родительской сценой |

Основная сцена занимает около 1.53s на desktop, 1.27s на телефоне после старта; фон заканчивает вход за 1.6/1.32s. Во время входа нет отдельного полёта точки, поворота персонажа или покадрового изменения фирменных контуров. После входа запускается отдельный lifecycle покачивания утки.

Если группа ниже видимого окна (например, опыт на планшете), её вход ждёт попадания в экран. Если пользователь успел прокрутить страницу во время подготовки, Hero сразу показывается статично.

## Образец для контентных разделов

- «Идеи — в дело»: заголовок/описание поднимаются на 52/32px за 1050/900ms. Макеты независимо входят после появления самого макета в поле зрения: подъём 88/54px, масштаб .96 → 1, дополнительный поворот ±5/0°, 1300/1100ms. Исходные наклоны сохраняются.
- «Как мы работаем» переведён на общий контентный ритм: независимые цели без задержек по номерам и без поворота утки. Подробности — CONTENT-MOTION.md.
- IntersectionObserver: threshold .12, rootMargin `0px 0px -10% 0px`. Один вход на элемент, без повторов и циклов.

## Ввод, доступность и lifecycle

- Клавиатурный фокус или pointerdown внутри шапки/Hero сразу завершают весь Hero и снимают подготовительные классы. Движение не мешает открытию меню и использованию CTA.
- Reduced motion отключает входы; включение настройки во время движения отменяет эффекты и снимает все подготовительные скрытия.
- Resize завершает Hero и отменяет текущие эффекты остальных двух разделов. Отложенная готовность SVG не запускает отменённый Hero снова.
- `pagehide` освобождает observer, timeout, listeners, подготовительные классы и анимации. Возврат из BFCache оставляет статичную страницу. Повторная инициализация сначала уничтожает предыдущий экземпляр.

## Проверка общего входа до добавления покачивания

Chrome, localhost 4330. Сценарий — `output/implementation/check-hero-orchestration.cjs`; отчёт и снимки — `output/qa/hero-orchestration/`.

- 320, 390, 768, 1024, 1920px: финальные рамки Hero/иллюстрации/опыта и следующих двух разделов совпали с исходным checkpoint с допуском <1px. Переполнения нет ни в промежуточном кадре, ни в финале.
- У всех активных групп Hero совпал startTime. На исходном SVG нет отдельной анимации, движется родитель сцены. На экране единственная иллюстрация из оригинального файла.
- Просмотрены промежуточные desktop/mobile снимки. При обычном воспроизведении через 650ms активны все семь групп, после завершения нет удерживаемых эффектов.
- На 768px проверен отложенный вход опыта при прокрутке к нему. На телефоне проверены фокус CTA во время входа и открытие/закрытие меню.
- Включение reduced motion во время входа оставило 0 активных эффектов и 0 подготовительных классов. При загрузке с этой настройкой сцена видима.
- SHA-256 десяти защищённых файлов совпали с checkpoint: общая прокрутка, витрина, Архитектоника, чемодан, roof/admin и исходный SVG не изменены.
- Сборка, проверка ссылок/бюджетов и существующая проверка палитры прошли. Дополнительные CSS/JS около 3.2KiB gzip.

Полная регрессия витрины, Lighthouse и физический телефон в эту итерацию не входили. Проверка двух SVG-слоёв и отдельного покачивания — в HERO-DUCK-IDLE.md. Предыдущие отчёты `page-motion-pilot/` и `page-motion-retiming/` относятся к отвергнутым версиям входа Hero, а не к текущей динамике.
