# Форма заявки Producta

Текущий этап: локальная интерактивная заготовка. Endpoint и получатель заявок не определены. Сетевых запросов, серверного сохранения и сообщения об успешной доставке нет. Текст политики в dialog — явная заготовка до запуска.

Владельцы: src/index.html — поля и тексты; src/styles/home.css — оформление и адаптация; src/js/home.js — клиентская проверка и открытие политики.

| Поле | Контракт |
|---|---|
| services | Ноль или несколько значений: strategy, branding, web, automation, communications, full-cycle. Читать через FormData.getAll. |
| budget | Необязательное одно значение: 50-200, 200-400, 400-600, 600-plus. Диапазоны в тысячах рублей. Повторная активация выбранного варианта снимает выбор. |
| task | Обязательно, непустой после trim, до 3000 символов. |
| name | Обязательно, непустой после trim, до 120 символов. |
| phone | Обязательно, 10–15 цифр, допускаются +, пробелы, точки, скобки и дефисы; до 32 символов ввода. |
| email | Необязательно, native type=email, до 254 символов. |
| question | Необязательно, до 500 символов. |
| consent | Обязательный checkbox, по умолчанию не выбран; значение yes. |

Ввод сохраняется в текущем DOM после локальной проверки. Ошибки обязательных полей, телефона и email блокируют отправку. Выбор услуг и одного бюджета не требует JavaScript; снятие выбранного бюджета повторным кликом или пробелом добавлено через JavaScript. Без JavaScript кнопка проверки отключена.

Для настоящей отправки потребуется отдельный серверный обработчик с повторной валидацией, защитой от спама и согласованным ответом о приёме заявки; получатель и действующая политика пока не заданы. Секреты и ключи не размещать во frontend.

Точечная проверка текущего компонента: output/implementation/check-request.cjs. Результат — output/playwright/contact-request-check.json. Снимки 1440px и 390px — contact-request-desktop.png и contact-request-mobile.png в той же папке. Lighthouse и полный регрессионный прогон в этой итерации не выполнялись.
